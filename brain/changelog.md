2026-10-24 — v0.9.1: the elevated self-tests ran on this PC (all pass: service control, SYSTEM process, process actions, Ryzen SDK 47-52 °C). They exposed that the app's SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32) (0.8.0 hardening) breaks AMD's SDK inside the app: its Device.dll load uses LOAD_WITH_ALTERED_SEARCH_PATH, which Windows rejects with error 87 once default DLL directories are set. Proven by GOTM_SDK_EMULATE runs (dlldirs FAIL, comsec PASS, both FAIL) and gotm.exe --ryzen-probe. main.go now uses SetDllDirectory("") (drops the current directory only; every DLL gotm/walk/win/wingoes load is already System32-qualified). Also: ryzensdk.go initPlatform reports the Windows error and takes vendor/cpuOnly, new metrics/ryzenprobe.go + gotm.exe --ryzen-probe FILE, elevated_test.go GOTM_SDK_EMULATE hook, tools/elevated-check.ps1 (quoting fix, emulation runs, probe, AMD sample control, capture try/catch), tools/setup shortcut thread pin.
